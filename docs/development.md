# Development

Requirements: Docker + Compose only. No Rust, Node or npm on the host.
Everything compiles, lints and tests inside `docker/Dockerfile` stages — nothing is written to the source tree.

Run commands from the repo root. Build cache lives in BuildKit; never a host `target/` or `node_modules/`.

## Gates

```bash
scripts/gates.sh                        # fmt + clippy + test + htmx
scripts/gates.sh                        # no image, no residual container
TEST_FILTER=<substring> scripts/gates.sh
```

- `fmt` — `cargo fmt --check`.
- `clippy` — `--all-targets --all-features --locked -- -D warnings`.
- `test` — builds the `fs-ez` binary first, then `cargo test --locked`.
- `htmx` — downloads pinned `htmx.org@2.0.11`, checks the SHA-256, compares the vendored copy.

Without Docker: `cargo fmt --check`, `cargo clippy --all-targets --all-features --locked -- -D warnings`, `cargo test --locked`.
`Cargo.lock` stays committed; every build is `--locked`.

## Dev server

```bash
scripts/build.sh --up                                      # build image + start dev server on :18678
docker compose -f docker/compose.dev.yml up --build --watch # build + sync static/, rebuild on code
docker compose -f docker/compose.dev.yml logs -f
docker compose -f docker/compose.dev.yml down
```

Dev server `up --build` does not run the gates; call `scripts/gates.sh` or use `scripts/build.sh --gates`.
Dev state: `../config` → `/config` (database, backups), `../data` → `/data` (files).
Dev user: `USERNAME=user`, password `PASSWORD=dev-password-1234`.
Production-like image + restart:

```bash
scripts/build.sh               # runtime image only
scripts/build.sh --gates --up  # gates, image, restart fs-ez
scripts/build.sh --up          # restart without rebuild
```

## CSS

`static/css/app.css` is generated by Tailwind in the `css` stage and committed for host builds.
Never edit it by hand. Source: `static/css/input.css` and `docker/package-lock.json`.

```bash
docker build -f docker/Dockerfile --target css --progress=plain -t fs-ez-css .
```

## Audit

HTTP security audit against the dev server (`:18678`): headers, auth, traversal, no-content, limits, injection, permissions.

```bash
docker compose -f docker/compose.dev.yml --profile audit up --build audit
```

## Release image

```bash
docker build -f docker/Dockerfile -t fs-ez:local .
docker build -f docker/Dockerfile --target runtime -t ghcr.io/fs-ez/fs-ez:latest .
```

Multi-arch release is built by CI: `v*` tag or manual dispatch, gates first, then amd64 + arm64.

## Cleanup

```bash
scripts/docker-clean.sh        # stack down, project images, BuildKit bounded
scripts/docker-clean.sh --all  # full BuildKit cache + multiarch builder
```

Bounds: `MAX_CACHE` (default 8 GB), `MIN_FREE` (default 10 GB).

## Layout

Workspace at the root, crates under `crates/`, final binary `crates/fs-ez`.

| Crate | Role |
| --- | --- |
| `fs-ez` | Binary, CLI bootstrap and `serve`. |
| `fs-ez-app` | Use cases: files, tags, views, groups, inbox, auth, settings, backup. |
| `fs-ez-core` | Domain types: IDs, filters, query AST, settings, paths. |
| `fs-ez-store` | Persistence traits, sync, `Arc<dyn Store>`. |
| `fs-ez-sqlite` | SQLite adapter, WAL, migrations, backup. |
| `fs-ez-fs` | Confined filesystem access. |
| `fs-ez-fingerprint` | BLAKE3 content fingerprints. |
| `fs-ez-query` | TMSU query lexer/parser/evaluator. |
| `fs-ez-cli` | Argument parsing and output rendering. |
| `fs-ez-web` | axum router, askama templates, htmx, WebDAV, SSE. |
| `fs-ez-test-support` | Test layout guard. |

Rules:

- Dependencies strictly downward: `fs-ez-app` never depends on `rusqlite`, `axum` or `fuser`.
- Web and CLI are two adapters of `fs-ez-app`; no shell or HTTP between them.
- Store traits are synchronous; every blocking call from web goes through `tokio::task::spawn_blocking`.
- SQLite is the only source of truth. WAL, `foreign_keys=ON`, `busy_timeout=5s`, migrations under `BEGIN IMMEDIATE`.
- Paths are stored as Unix-byte BLOBs + lossy `path_display`; JSON never fails on a non-UTF8 path.
- Typed IDs (`FileId`, `TagId`, …) in public APIs, never bare `i64`.
- `panic = "abort"`, `#![forbid(unsafe_code)]`; user input always returns `Result`.
- fs-ez never serves file content through `/api`; WebDAV is the only content path.

## Tests

No inline `#[cfg(test)] mod tests { … }`. Use a sibling `tests.rs`
(`src/auth/totp.rs` → `src/auth/totp/tests.rs`; source only declares `#[cfg(test)] mod tests;`).
Root module: `src/lib.rs` → `src/tests.rs`. Several themes: a `tests/` directory.
`*_test.rs` (`src/layout_test.rs`) is a test file and may contain tests.
Each crate runs `fs_ez_test_support::layout::assert_tests_outside_sources`; an inline test fails the suite.

See `AGENTS.md` for the full contributor rules.
